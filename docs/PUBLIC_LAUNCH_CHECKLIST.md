# Public Launch Checklist

Use this before making the GitHub repository public.

## Repository settings

- Name: `coding-agent-guidelines`
- Description: `Drop-in behavioral guidelines for Claude Code, Cursor, and AI coding agents.`
- Website: optional, use the README first.
- Visibility: public.

## Suggested GitHub topics

`ai`, `coding-agent`, `claude-code`, `cursor`, `developer-tools`,
`prompt-engineering`, `ai-coding`, `mcp`, `agentic-ai`, `best-practices`,
`software-engineering`, `claude`

## First release

- Create tag `v1.0.0` after the first public push.
- Release title: `coding-agent-guidelines v1.0.0`.
- Release notes: mention Claude Code, Cursor, Skill, plugin marketplace, and
  worked examples.

## README quality check

- Problem is clear in the first screen.
- 3-command quick start is visible.
- Install options are separated by tool.
- License and security policy are present.
- Issue templates and PR template are present.
- No placeholder owner/repo URLs remain.

## Social launch copy

Short:

> I open-sourced coding-agent-guidelines: a drop-in rule set for Claude Code,
> Cursor, and AI coding agents so they read first, make smaller diffs, and verify
> before claiming done.

Long:

> AI coding agents are powerful, but they fail in boring, repeatable ways: vague
> assumptions, drive-by rewrites, premature abstractions, no verification, and
> tool/context bloat. I packaged the rules I use into a public repo with
> CLAUDE.md, Cursor rules, a Claude Code Skill, plugin layout, and worked
> examples.
